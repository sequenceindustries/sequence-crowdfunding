# Technical decisions

- **Modular monolith**: one Flask app, one blueprint per area. Funding-model rules live in a registry (`services/campaigns.py`) so one model cannot change another's behaviour.
- **Auth**: signed server-side session cookie, Argon2 password hashes, header CSRF token on authenticated writes, rate limits on auth and upload. Staff accounts are created only through the CLI (`flask create-staff`), never the public API.
- **RBAC** is enforced per route by `roles_required`. Other users' resources return 404, not 403, so ids are not disclosed.
- **Campaign states**: draft → submitted → (changes_requested ↔ submitted) → approved → published. Reject and suspend are reviewer actions. Every decision needs a reason and is audited. Only approved campaigns can be published, by their owner.
- **Private files**: random storage keys outside any web path, magic-byte validation, 15 MB cap, 5-minute user-bound download links, staff access only while the linked campaign is under review, every link issue audited.
- **AI layer**: provider interface and registry. Providers flagged `external` need explicit user consent before any text is sent. Per-user daily limit, usage logged, output schema validated, provider errors never leak details. The bundled provider is a keyword-coverage scorer (not an LLM) and publishes its weights in every report.
- **Money**: integer cents, ZAR only. Public pages say nothing is raised until confirmed payment records exist.
- **Frontend**: Next 16 (async `params`), `/api/*` proxied to Flask so cookies stay first-party. Public pages are server-rendered; dashboard, login and register are `noindex` and disallowed in robots.txt.
- **Deck generator**: slides are built only from questionnaire text. Optional sections with no answer get no slide; essentials (cover, problem, solution, funding) always get one, flagged incomplete with a prompt. A funding total that does not match the request is flagged, never corrected. Unedited slides keep their flags when the client saves; edited slides are re-checked from content. PPTX export is refused (409) while anything is incomplete unless the founder explicitly forces it, and forced exports stamp each unfinished slide as a draft.
- **Finance engine**: integer cents and basis points, half-up rounding, pure functions with hand-calculated tests. The consistency checker compares only figures the founder entered (funding vs use of funds, annual vs monthly revenue, missing expenses, stated vs computed runway) and says a clean result does not mean the figures are accurate.
- **Email tokens**: random 256-bit tokens, only a SHA-256 hash stored, single use (atomic claim), purpose-bound, 24 h (verify) / 1 h (reset). At most 3 per user per hour; a newer link replaces older ones. Forgot-password answers identically for known and unknown emails. A weak new password is rejected before the link is consumed. Reset bumps `session_version`, which signs out every existing session. Links are redeemed by a button press, not on page load, so mail scanners cannot burn them. The mail sink is a dev outbox table; a real provider is still needed.
- **Verified email is required** to submit a campaign or contribute. The campaign page shows the owner's real email-verification state instead of a constant.
- **Payments**: provider interface with `simulated` flag. `CONTRIBUTIONS_MODE` (off / simulated / live) must match the provider kind, otherwise it acts as off, so a test provider can never take real money and a live provider is never labelled test mode. Status changes only through HMAC-signed webhooks (unsigned or unconfigured = rejected), each event id applies once, amounts must match, out-of-order events are ignored and recorded. Supporters must send an `Idempotency-Key` and confirm they understand it is not an investment. Contributions are R20 to R50 000.
- **Money shown publicly** comes only from non-simulated records and keeps confirmed, pending, refunded and failed/cancelled apart. Platform revenue counts only confirmed real pitch-deck fees; contributions belong to campaigns, refunded and simulated payments are excluded. Refunds are admin-only, need a reason, and take effect only when the provider confirms.
- **Pitch-deck fee (provisional decision)**: R500 buys *package* = analysis plus improvement report for one deck. Charging needs an explicit flag AND an active payment mode; the founder must confirm the exact amount each time, so a price change can never charge anyone unknowingly. A fee service of `generation` is refused because export gating is not built. Changing the service is a config edit.
- **Reconciliation** compares a provider settlement statement with our records and reports amount/status mismatches, rows we do not know, payments the provider lacks, and duplicates.
- **Public caching**: campaign, business and update pages are never cached (suspension, privacy and money changes must show on the next load); list pages cache for 30 s. This came from a bug found while testing, where stale data survived server restarts.
- **Follow and updates**: updates go live immediately, are labelled owner-reported, and can be hidden by staff with a recorded reason. A suspended campaign's updates and follows disappear with it.
- **Verification documents**: PDF/PNG/JPG, private, own download-token salt so deck links cannot open them. Reviewers see only `pending` documents; escalated ones are admin-only. Every decision needs a reason, is audited and emails the owner. Badges (`identity_checked`, `business_documents_reviewed`) come only from an approved document of that kind; uploading alone proves nothing.
- **Campaign review assistant**: rule-based, returns checks and compliance flags (return/risk-free claims, unsourced figures, pressure wording). It never edits the campaign. Provider capabilities are optional methods on the provider interface; external providers are refused until a consent flow exists for draft text.
- **Transparency statement**: built only from the owner's figures plus fixed platform statements, private until the owner approves, shown publicly only while the campaign is published and unchanged since approval (hash check). Verification status inside it is rendered live. Owner-written risk and update-plan notes are labelled as the owner's.
- **Staff UI** at `/staff` (noindex): campaign and verification queues with mandatory reasons.
- **Discovery**: keyword search, not AI. Words are split, stopwords dropped, every remaining word must appear in title, category, business name, location, summary or description (so more words narrow results). Relevance weights title 5, category/business/location 3, summary 2, description 1. Each result lists which fields matched, taken from the data. `%` and `_` are never wildcards. Published campaigns only. Sort options: relevance, recent, title, goal. There is no sponsored placement: nothing is sold, so nothing is promoted.
